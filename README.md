# QingZoneX Portal

Official portal and documentation site for the first QingZoneX open-source release: **QTable** and **QTableUI**.

## Stack

- Astro 7
- Starlight
- Static output for GitHub Pages
- No runtime database or server dependency
- Vanilla JavaScript for the interactive product tour

## Requirements

- Node.js 22.12 or newer
- npm 10 or newer

## Local development

```bash
npm ci
npm run dev
```

Open the URL printed by Astro, normally `http://localhost:4321`.

## Production build

```bash
npm ci
npm run build
npm run verify:dist
```

## GitHub Pages deployment

The repository includes `.github/workflows/deploy.yml` and automatically adapts its base path:

- In `boychina/qingzonex.github.io`, Pages is expected under `/qingzonex.github.io/`.
- After transferring the repository to the `QingZoneX` organization, the same code automatically switches to the organization root Pages URL because the repository name becomes `QingZoneX/qingzonex.github.io`.
- When a custom domain is introduced later, set the repository-level Actions variable `SITE_URL` to the canonical URL. The build will switch back to `/` as the base path.

In **Settings → Pages**, select **GitHub Actions** as the source.

See [DEPLOYMENT.md](DEPLOYMENT.md) for the full private-development, organization-transfer, Pages-launch, and custom-domain procedure.

## Reproducible installs

`package-lock.json` is generated by npm 10 on Node.js 22 and is committed to the repository. CI and Pages deployment both use `npm ci`; dependency changes must update and commit the lockfile together with `package.json`.

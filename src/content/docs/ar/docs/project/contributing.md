---
title: دليل المساهمة
description: اختيار مدخل المساهمة الصحيح بين qtable-server وqtable-web والبوابة.
---

QTable منتج واحد، لكن الكود يُصان في مستودعات مختلفة وفق حدود التنفيذ. قبل إرسال Issue أو Pull Request، اختر المستودع المسؤول عن القدرة.

## qtable-server

عند تعديل API أو نموذج البيانات أو الصلاحيات أو الأتمتة أو المرفقات أو التدقيق أو البحث أو OAuth أو خدمات الذكاء الاصطناعي، اقرأ [CONTRIBUTING.md في `QingZoneX/qtable-server`](https://github.com/QingZoneX/qtable-server/blob/main/CONTRIBUTING.md).

ويجب أن تحافظ تغييرات الخادم على عقود الصلاحيات والترحيل والتدقيق والكتابة الذرية والتوافق.

## qtable-web

عند تعديل مراكز العمل أو العروض أو Dashboard أو Automation أو التعاون أو البحث أو إمكانية الوصول أو التعريب أو تفاعلات الذكاء الاصطناعي، اقرأ [CONTRIBUTING.md في `QingZoneX/qtable-web`](https://github.com/QingZoneX/qtable-web/blob/main/CONTRIBUTING.md).

ويضم مستودع الواجهة فحوصًا للبناء والتبعيات والأمان والتراخيص والحاويات وعقود المنتج.

## البوابة والوثائق

يجب أن تُصان محتويات البوابة بالصينية المبسطة والصينية التقليدية والإنجليزية معًا، وأن يكون المصدر الواقعي هو الكود الحالي وملفات الإصدار وحالة Release وIssues في المستودعات العامة. ولا تكتب قدرات الخارطة كأنها مُسلَّمة، ولا تعادل حالة الكود العام بحالة منتجات الإصدار المنشورة.

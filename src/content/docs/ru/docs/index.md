**QTable** — открытый продукт, который сейчас представляет QingZoneX: AI-native система управления проектами и работой на основе многомерных таблиц.

С точки зрения пользователя QTable — цельный продукт; с точки зрения инженерии он состоит из двух публичных репозиториев реализации. Оба слоя используют одну модель Table / Record / View / Dashboard / Permission и работают вместе через контракты REST / GraphQL / WebSocket / Auth / OAuth.

- [`QingZoneX/qtable-server`](https://github.com/QingZoneX/qtable-server) — бэкенд FastAPI / Strawberry GraphQL, модель данных, права, автоматизация, аудит, вложения, поиск, OAuth и ИИ-сервисы.
- [`QingZoneX/qtable-web`](https://github.com/QingZoneX/qtable-web) — приложение React, центры работы, Grid / Kanban / Gantt / Calendar / Gallery, дашборды, совместная работа, автоматизация и ИИ-взаимодействие.

Оба репозитория сейчас работают на базе **`v0.1.1-alpha` / Open Source Preview** под **Apache License 2.0**. Публичный репозиторий не означает выпущенный GitHub Release, Docker-образ или другой артефакт; смотрите [статус релиза](./project/release-status/) и Releases каждого репозитория.

## Рекомендуемый порядок чтения

1. Запустите полный QTable локально по [быстрому старту](./getting-started/quick-start/).
2. Прочитайте [архитектуру QTable](./qtable/architecture/), чтобы понять границы Web, API, данных и хранилища.
3. Изучите [обзор продукта QTable](./qtable/overview/) для текущей базы возможностей.
4. Для фронтенд-реализации и локальной разработки — [разработка фронтенда](./qtable-ui/development/).
5. Перед публичным развёртыванием проверьте [модель безопасности](./qtable/security/) и [чек-лист production](./getting-started/production-checklist/).
6. Используйте [матрицу возможностей](./project/feature-matrix/), чтобы отличать реализованное, укрепляемое и запланированное.

:::caution[Статус Alpha]
Текущая версия подходит для оценки, разработки сообществом, staging и контролируемых проб. До v1.0 публичные API, поведение миграций и часть продуктовых контрактов могут меняться.
:::

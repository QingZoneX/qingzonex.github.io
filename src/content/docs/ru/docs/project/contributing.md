---
title: Руководство по участию
description: Выбор правильной точки входа между qtable-server, qtable-web и порталом.
---

QTable — один продукт, но код поддерживается в разных репозиториях по границам реализации. Перед отправкой Issue или Pull Request выберите репозиторий, отвечающий за возможность.

## qtable-server

При изменении API, модели данных, прав, автоматизации, вложений, аудита, поиска, OAuth или ИИ-сервисов прочитайте [CONTRIBUTING.md репозитория `QingZoneX/qtable-server`](https://github.com/QingZoneX/qtable-server/blob/main/CONTRIBUTING.md).

Изменения сервера должны сохранять контракты прав, миграций, аудита, атомарной записи и совместимости.

## qtable-web

При изменении центров работы, представлений, Dashboard, Automation, совместной работы, поиска, доступности, i18n или ИИ-взаимодействий прочитайте [CONTRIBUTING.md репозитория `QingZoneX/qtable-web`](https://github.com/QingZoneX/qtable-web/blob/main/CONTRIBUTING.md).

Репозиторий фронтенда содержит проверки сборки, зависимостей, безопасности, лицензий, контейнеров и продуктовых контрактов.

## Портал и документация

Контент портала должен поддерживаться на упрощённом китайском, традиционном китайском и английском, а источником истины — текущий код, файлы версий, состояние Releases и Issues публичных репозиториев. Не описывайте возможности дорожной карты как поставленные и не отождествляйте состояние публичного кода с опубликованными артефактами.
